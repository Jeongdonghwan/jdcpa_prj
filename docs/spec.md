# 회생OK(hoesaengok.com) + 종합 생활 솔루션(everyday.hoesaengok.com) 구조·SEO 분석 및 개발 스펙

- 작성일: 2026-10-05
- 분석 방법: WebFetch 기반 약 45회 페이지/사이트맵 조회. WebFetch는 HTML을 요약·마크다운으로 변환해 돌려주므로 JSON-LD, rel 속성, iframe, lazy-loading 등 원시 HTML 수준 정보는 "미확인"으로 표기했다. 관찰(실제로 본 것)과 추정(정황 기반)은 구분해서 적는다.
- 용도: 같은 구조의 CPA 리드 사이트를 Flask + Jinja2 + MariaDB(Cafe24 가상서버)로 만들기 위한 기획·개발 스펙. 섹션 6~10이 개발 스펙(v2)이며 클로드코드에 바로 넘길 수 있게 썼다.

내부 링크 흐름(관찰):
- 홈 → 서비스 피커 → 지역 피커 → `/{시도}-{서비스}`. "많이 찾는 지역 서비스" 6개 회전 딥링크.
- 시도 허브 → 시군구 10개 + 서비스 10개. 시군구 허브 → 동 목록 + 서비스 8개. 동 허브 → 서비스 8개만.

## 6. 개발 스펙 v2 — 아키텍처 (Flask + Jinja2 SSR + MariaDB, Cafe24 가상서버)

### 6.1 설계 원칙
- 참조 사이트의 "지역 x 서비스" 2차원을 "키워드 콤보"(버티컬 > 하위주제 > 의도 > 상황 > 직업/페르소나 > 지역 > 질문형) N차원으로 일반화한다. 모든 랜딩 페이지는 `keyword_combos` 한 행에 대응한다. 지역 허브·서비스 허브도 콤보의 특수형(차원 일부가 NULL)으로 취급해 라우팅·사이트맵·보고를 한 축으로 통일한다.
- CPA 네트워크는 어댑터로 추상화한다. 페이지는 "오퍼(offer)"만 알고, 오퍼가 어떤 네트워크·어떤 연동 방식(리다이렉트/임베드/스크립트/자체 폼/전화·카카오)인지는 `offers` 설정이 결정한다. 네트워크·오퍼 추가는 관리자 입력만으로 끝나는 것을 목표로 하고, 포스트백 서명 검증처럼 코드가 필요한 부분만 어댑터 클래스로 둔다.
- 런타임에 LLM 호출 없음. 생성·검수·버전 관리는 파이프라인(배치)에서 끝내고 결과를 `page_contents`에 저장한다. 요청 시에는 저장된 블록을 조립만 한다.
- 모든 출력은 "품질 게이트"를 통과한 것만 index. 게이트: 고유성 점수, 컴플라이언스 린트, 실데이터 블록 존재, 검색량/우선순위 임계값.

### 6.2 구성도(텍스트)
```
[nginx] ──> [gunicorn: Flask app]
             ├─ web_bp        : 공개 페이지(콤보 라우팅, 허브, 블로그, 도구)
             ├─ go_bp         : /go/{offer_slug}  클릭 리다이렉터(click_id 발급, 매크로 치환, 로그)
             ├─ lead_bp       : /lead/{offer_slug} 자체 폼 수신 → 동의 저장 → 전달 어댑터(API/webhook/email/sheet)
             ├─ postback_bp   : /postback/{network_slug} 전환 수신(시크릿/IP 검증, 필드 매핑, 중복 제거)
             ├─ seo_bp        : robots.txt, sitemap-*.xml, rss-*.xml, indexnow 큐 처리 트리거
             └─ admin_bp      : 관리자(네트워크/오퍼/풀/콤보/검수/보고)
[MariaDB]   regions, verticals, keyword_*, offers, networks, clicks, conversions, page_contents, pages, posts ...
[배치(cron)] keyword_research → combo_generate → content_generate(Claude) → quality_gate → publish → sitemap/indexnow
             gsc_ingest, naver_sa_ingest, rank_track, prune_merge, log_analyze, report_rollup
[외부]       CPA 네트워크 N개(어댑터), 네이버 검색광고 API, GSC API, 네이버 서치어드바이저(수동 export), IndexNow 엔드포인트
```
- 서버 1대(Cafe24 가상서버) 전제. 배치는 시스템 cron + Flask CLI(`flask jobs <name>`). 큐는 DB 테이블(`job_queue`)로 대체, Redis·Celery 미사용.
- 캐시: `pages.rendered_html` + nginx proxy_cache(5~10분). 트래픽이 늘면 정적 HTML export로 전환 가능하도록 템플릿은 요청 컨텍스트 의존을 최소화한다.

### 6.3 도메인 구조 결정(서브도메인 vs 디렉터리)
| 관점 | 서브도메인(참조 사이트 방식) | 디렉터리(`/법률/…`, `/이사/…`) |
|---|---|---|
| 네이버 | 서브도메인을 별도 사이트로 취급. 사이트 단위 평가가 분리되어 한 버티컬의 저품질이 다른 쪽에 덜 번짐. 반대로 신뢰 축적도 분리됨. 등록·사이트맵·RSS 모두 따로. | 사이트 하나로 평가. 블로그·도구로 쌓은 신뢰가 전 버티컬에 공유. |
| 구글 | 대체로 같은 사이트로 보지만 서브도메인은 섹션별로 다르게 평가될 수 있음. | 권한(authority) 집중에 유리. |
| 운영 | 버티컬 매각·분리 용이, 인증·사이트맵 N배. | 단순. |
| 권장 | **법률(개인회생) 전문 사이트는 루트 도메인에, 2번째 버티컬부터는 처음엔 디렉터리로 시작**해 사이트 하나의 신뢰를 키우고, 버티컬이 독립 브랜드가 될 만큼 커지면 서브도메인 또는 별도 도메인으로 분리한다. 참조 사이트가 서브도메인에 10개 버티컬을 몰아넣은 것은 리스크 격리 목적으로 보이며(추정), 우리는 초기 자원이 한 사이트에 집중되어야 하므로 디렉터리가 유리하다. | |

## 7. CPA 네트워크 범용 연동 계층

### 7.1 개념 모델
```
networks(네트워크) 1──N offers(오퍼/캠페인) 1──N offer_placements(페이지 유형·슬롯별 노출 설정)
offers ──N clicks ──N conversions
offers ──1 integration_mode ∈ {redirect, iframe, script, own_form, phone, kakao}
```
- **network**: 광고 플랫폼 또는 직거래 광고주. 추적 URL 규약(`{click_id}` 매크로 파라미터명, sub-id 개수), 포스트백 유무·방식(GET/POST, 서명/시크릿/IP), 리포트 API 유무, 통화·정산 주기.
- **offer**: 네트워크 안의 개별 캠페인. 버티컬, 광고주명, 단가 유형(CPA/CPL/CPS/CPC), 단가(payout), 커버리지 지역, 기간, 상태, 필수 표기(광고책임변호사, 사업자명, 대부업 등록번호 등 버티컬별 compliance_fields), 소재(로고, 소개문, 배지), 연동 방식과 그 파라미터(JSON).
- **placement**: 어떤 콤보/페이지 유형/슬롯(상단 CTA, 카드 그리드, 중단 폼, 플로팅 버튼)에 어떤 오퍼를 어떤 가중치로 노출할지. 기본은 자동 선택 엔진이 결정하고, placement는 수동 고정·제외·A/B 슬롯용.
- 네트워크 예시(연동 전 각 네트워크 문서 확인 필요, 아래는 매핑 대상의 예일 뿐 API·포스트백 지원 여부를 확인한 것이 아니다): 리플라이알바(참조 사이트가 사용, `/pt/{code}` 링크·`_frm` 임베드 폼 관찰됨), 국내 CPA·제휴 플랫폼(링크프라이스, 애드픽, 텐핑, 디비디비딥, 쿠팡 파트너스(CPS), 네이버 커넥트형 제휴 등), 광고주 직거래(법무법인·이사업체와 건당 정산), 해외형(Impact, CJ 등 CPS). 각각 추적 파라미터명·포스트백 가능 여부가 다르므로 `networks.conventions` JSON에 기록한다.

### 7.2 연동 방식(integration_mode)별 동작
| 모드 | 페이지 출력 | 클릭 추적 | 전환 수집 | 개인정보 책임 | 비고 |
|---|---|---|---|---|---|
| redirect | `<a href="/go/{offer_slug}?p={page_id}" rel="sponsored nofollow noopener" target="_blank">` | 자체 리다이렉터에서 click_id 발급 후 네트워크 추적 URL로 302 | 네트워크 포스트백(있으면) 또는 CSV 수동 임포트 | 없음(외부에서 수집) | 참조 사이트 `/pt/{code}` 대응 |
| iframe | `<iframe src="{embed_url}?sub={click_id}" loading="lazy" title=…>` | iframe 로드 시 서버에서 view 로그 + 클릭은 추적 불가(네트워크 측에서만) | 포스트백/CSV | 없음(폼 운영 주체 외부, 정책에 명시) | 참조 사이트 `_frm` 폼 대응. sub 파라미터 지원 여부는 네트워크 확인 |
| script | 네트워크 제공 위젯 `<script>` 삽입(CSP 허용 목록 관리) | 네트워크 측 | 포스트백/CSV | 없음 | 성능 영향 → 지연 로드 |
| own_form | 자체 HTML 폼(이름/연락처/지역/희망시간 + 동의 체크 2종) → `/lead/{offer_slug}` POST | 서버에서 lead 저장, click_id 연계 | 전달 어댑터가 API/webhook/email/Google Sheet로 송신. 전달 결과·외부 lead_id 저장. 전환은 광고주 확정 후 CSV/API로 반영 | **있음**: 개인정보 수집·이용 동의, 제3자 제공 동의(광고주명·항목·목적·보유기간 명시), 처리방침 갱신, 보유기간 후 파기 배치, 암호화 저장(연락처 AES), 접근 로그 | 참조 사이트가 피한 책임을 떠안는 대신 리드 품질·단가 협상력이 생김. 변호사 광고·변호사법 쟁점은 11장 리스크 참조 |
| phone | `<a href="tel:…">`(모바일) / 번호 표시 + 클릭 로그 | `/go/...?mode=tel` 경유 또는 JS beacon | 통화 추적 번호(네트워크·콜트래킹 업체 제공 시) 또는 수동 | 없음 | 전화 CPA 오퍼용 |
| kakao | 카카오톡 채널/오픈채팅 링크 | `/go/` 경유 | 수동 | 없음 | |

### 7.3 클릭 리다이렉터 `/go/`
```
GET /go/<offer_slug>?p=<page_id>&s=<slot>&k=<keyword_id>&ab=<variant>
1. offer 조회(active, 기간 내). 없으면 fallback offer 또는 404.
2. click_id = base62(uuid4) ; clicks INSERT (offer_id, page_id, combo_id, region_id, keyword_id, slot, variant,
   ua_hash, ip_hash(일 단위 salt), referrer, ts, is_bot(UA/빈도 규칙))
3. 추적 URL 조립: offer.tracking_url_template 에 매크로 치환
   지원 매크로: {click_id} {page} {region_slug} {region_full} {keyword} {combo_id} {slot} {variant} {site} {utm_source} {utm_medium} {utm_campaign}
   예) https://net.example/pt/ABC?sub1={click_id}&sub2={region_slug}&sub3={keyword}
   네트워크별 sub-id 개수·길이 제한은 networks.conventions.max_sub_len 로 잘라냄.
4. 302 Location: 치환 URL. 응답 헤더 Cache-Control: no-store. 봇(is_bot)은 로그만 남기고 동일 302.
5. robots.txt: Disallow /go/ , 링크 rel="sponsored nofollow".
```

### 7.4 전환 포스트백 `/postback/<network_slug>`
- 메서드·파라미터는 네트워크 설정(`networks.postback` JSON): `{method, click_id_param, status_param, amount_param, event_param, secret_param|hmac_header, ip_allowlist[], status_map{approved:..., pending:..., rejected:...}}`.
- 처리: IP·시크릿 검증 실패 → 403 + 로그. click_id 조회 실패 → `conversions_orphan`에 저장(후속 매칭). 성공 → `conversions` UPSERT(dedup key = network_id + external_id 또는 click_id + event). 상태 변경(pending→approved/rejected)은 같은 행 갱신 + 이력 테이블.
- 포스트백이 없는 네트워크: 관리자에서 CSV 업로드(열 매핑 UI 저장 → `networks.csv_mapping`), 매칭 키는 click_id/sub-id 또는 (오퍼, 전환시각 ±N분, 지역) 근사 매칭을 "추정 매칭" 플래그로 저장.
- 리포트 API가 있는 네트워크: 어댑터 `pull_conversions(since)` 구현 → 일 1회 cron.

### 7.5 어댑터 인터페이스(코드가 필요한 부분만)

- 서명이 HMAC 등 비표준이거나 API 폴링이 필요한 네트워크만 서브클래스 1개 파일 추가. 그 외는 관리자 입력(추적 URL 템플릿, 포스트백 파라미터 매핑, 시크릿, IP)만으로 신규 네트워크 등록.

### 7.6 오퍼 선택·로테이션 엔진
```
select_offers(combo, slot, n):
  cand = offers.filter(vertical=combo.vertical, active, now in [start,end], region_scope ∋ combo.region.sido or empty,
                       topic_scope ∋ combo.topic or empty, compliance_ok(=필수 표기 필드 모두 채워짐))
  cand = cand.exclude(daily_cap_reached or monthly_cap_reached)
  placements 수동 고정(pin) → 최우선 / 제외(block) → 제거
  score = w1*EPC_7d(normalize) + w2*payout(normalize) + w3*manual_weight − w4*recent_reject_rate
          (EPC 데이터가 n_clicks<50 이면 payout·manual_weight만 사용: 콜드스타트)
  rng = Random(sha256(site|combo.id|slot|ranking_version))   # 페이지별 결정적
  weighted_shuffle(cand, score, rng)  → 상위 n
  A/B: ab_tests 활성 시 variant = hash(click_cookie|test_id) % arms → 슬롯 오퍼/문구 교체, variant를 /go/ 에 전달
  결과 0개면 fallback_offer(vertical) → 그것도 없으면 슬롯 비표시(빈 CTA 금지)
```
- `ranking_version`은 EPC 재계산 배치(일 1회)에서 증가 → 페이지 캐시 재조립. 결정성과 재랭킹을 둘 다 만족.
- 폼 임베드 슬롯(form_offer)은 버티컬별 기본값 + 지역 범위 오버라이드.

### 7.7 보고
- 롤업 테이블 `stats_daily(date, site_id, page_id, combo_id, offer_id, region_id, keyword_id, slot, variant, impressions, clicks, leads, conv_pending, conv_approved, revenue)`.
- 지표: CTR(클릭/노출), CVR, EPC = revenue/clicks, RPM = revenue/노출*1000, 오퍼별 승인율, 지역별·키워드별 EPC. 관리자 대시보드 + CSV export.
- 노출(impression)은 서버 렌더 시 슬롯 단위 카운트(봇 제외)로 집계.

### 7.8 컴플라이언스 필드
- `verticals.compliance_schema` JSON: 예) 법률 `{required:['ad_lawyer'], badges_forbidden:['1위','최고'], disclaimer_ids:[...]}`; 대부·금융 `{required:['registration_no','warning_text']}`; 보험 `{required:['agency_name','agency_reg_no']}`; 의료 `{required:['medical_ad_review_no']}`.
- 오퍼 저장 시 스키마 검증, 미충족 오퍼는 `compliance_ok=0` → 선택 엔진에서 제외.
- 모든 외부 광고 링크: `rel="sponsored nofollow noopener"`, 카드 상단 "광고" 또는 "제휴" 라벨, 페이지 상단 근접 위치에 수수료 고지 1줄.

## 8. 대규모 키워드 공간

### 8.1 차원 모델
```
vertical(버티컬) > topic(하위 서비스/주제) > intent(의도 수식어) > situation(상황) > persona(직업/대상) > region(지역: 시도/시군구/동 + 생활권·역세권·관할법원 별칭) > question(질문형)
```
한 콤보 = 각 차원에서 0~1개 항목 선택. 모든 차원이 NULL인 것은 버티컬 허브. 실제로 페이지가 되는 조합은 임계값(8.4)을 넘는 것만.

### 8.2 시드 목록(버티컬별, 초기 적재용 — 실제 검색량으로 걸러서 사용)

- intent: 비용, 수임료, 가격, 후기, 추천, 비교, 잘하는곳, 방법, 절차, 기간, 서류, 자격, 조건, 무료상담, 상담, 변호사, 법무사, 법무법인, 신청, 기각사유, 단점, 불이익

- persona: 직장인, 자영업자, 프리랜서, 무직, 주부, 공무원, 군인·경찰, 간호사·의료인, 택배·배달기사, 택시·화물 기사, 대학생·20대, 30대, 40대, 50대 이상, 고령자, 사회초년생, 외국인(미확인: 수요·법적 가능성)
- region: 17 시도 / 약 250 시군구 / 읍면동(단계적) + 별칭: 관할 법원(서울회생법원, 수원회생법원, 부산회생법원, 각 지방법원 본원·지원), 생활권(강남권, 분당·판교, 일산, 동탄 등), 역세권(필요 시)
- question: "{topic} 신청하면 {situation}은 어떻게 되나요", "{persona}도 {topic} 가능한가요", "{region} {topic} 어디서 하나요", "{topic} {intent} 얼마나 드나요"

**이사·청소**
- topic: 포장이사, 반포장이사, 원룸이사, 용달이사, 사무실이사, 장거리이사, 보관이사, 입주청소, 이사청소, 거주청소, 사무실청소, 줄눈·탄성코트, 새집증후군(베이크아웃), 곰팡이 제거, 에어컨 청소, 매트리스 청소, 정기 가사청소
- intent: 비용, 견적, 가격, 평수별 비용(10평/20평/30평대), 후기, 추천, 비교, 업체, 잘하는곳, 체크리스트, 날짜(손 없는 날), 준비물, 소요시간
- situation: 신혼집, 신축 입주, 전세 만기, 급한 이사(당일·3일 내), 대형가전 있음, 피아노·금고, 반려동물, 복층, 엘리베이터 없음, 사다리차 필요, 주말·공휴일, 장마철
- persona: 1인가구, 신혼부부, 자녀 있는 가족, 어르신 부모님 집, 사무실 담당자, 임대인(원상복구)

### 8.4 콤보 → 페이지 결정 규칙
- **독립 페이지** 조건(둘 중 하나 이상): (a) 월 검색량 합(네이버 PC+모바일) ≥ 임계값(기본 30, 지역 콤보는 10), (b) 고유 콘텍스트 데이터 블록 ≥ 2개(관할 법원, 지역 통계, 상황별 체크리스트, 직업별 소득 증빙 안내 등 콤보 전용 데이터).
- 조건 미달 콤보는 **부모 콤보에 병합**: 부모 페이지의 "관련 질문/세부 안내" 블록에 H3 + 2~4문장으로 흡수하고, 콤보 상태는 `merged`(URL 생성 안 함) 또는 이미 URL이 있으면 `noindex` + 부모로 canonical.
- 부모 결정 순서: 가장 구체적 차원을 하나 제거(question → persona → situation → intent → region 하위 레벨 → topic). 예: `인천-부평구 개인회생 비용` 미달 → 부모 `인천 개인회생 비용`(있으면) → `인천-부평구 개인회생`.
- **카니벌라이제이션 그룹**: 동의어·조사 차이·어순 차이로 같은 의도인 콤보는 하나의 `cannibal_group_id`로 묶고 대표 콤보 1개만 index, 나머지는 대표로 301 또는 canonical. 예: "개인회생 비용 / 개인회생 수임료 / 개인회생 변호사 비용" → 대표 1개 + 나머지는 대표 페이지 H2로 흡수.
- 지역 x 수식어 x 상황 3중 조합은 기본 생성 금지(예: `인천 주식빚 개인회생 비용`). 상황·직업 콤보는 전국 페이지 1개만 두고 지역은 그 안의 "지역별 상담처 보기" 링크로 연결 → 지역 페이지와 경쟁하지 않는다.

### 8.7 콘텐츠 생성 파이프라인(Claude API)
- 모델 분담: Haiku = 리프·지역·상황 페이지 블록 대량 생성, FAQ, 메타; Sonnet = 버티컬/topic 허브, 필러 글, 도구 설명, 검수 리라이트.
- 입력(프롬프트에 주입하는 실데이터): 콤보 차원 값, 지역 실데이터(관할 법원·주소·전화, 인구·사업체 수, 지자체 지원제도 — `regions.*`, `region_facts`), topic 사실 블록(`topic_facts`: 법령 조문·요건·기간·비용 범위, 출처 URL), 버티컬 가격 범위(`price_ranges` by region, 있을 때만), 금지 표현 목록, 섹션 스키마(JSON으로 블록별 글자 수·H2 지정).
- 출력: JSON `{h1_candidates[3], meta_description, blocks:[{slot, html}], faqs:[{q,a}], internal_link_suggestions[]}` → `page_contents` 버전 행으로 저장.
- 프롬프트 템플릿은 page_type별 파일(`prompts/{page_type}.md`), 변수는 Jinja로 렌더. 템플릿 변경 시 `prompt_version` 증가.
- **고유성 검사**: 형제 페이지(같은 부모, 같은 page_type)와 5-gram shingle Jaccard ≤ 0.35, 임베딩 코사인 ≤ 0.90(선택). 초과 시 재생성(온도·시드 변경, "다음 표현을 피하라" 피드백 포함) 최대 3회, 실패 시 검수 큐.
- **컴플라이언스 린트**: 금지어(결과 보장, 100%, 무조건, 반드시 인가, 최고, 1위, 최저가 보장, 전액 면책 보장, 승소 보장, 비밀 보장 등), 법률 자문형 단정 문장 패턴("~하면 됩니다"→"~한 경우가 있습니다"), 수치 주장에는 출처 필수, 광고 고지 블록 존재. 위반은 자동 플래그 → 재생성 또는 사람 수정.
- **팩트 체크**: `topic_facts`에 없는 법령·기간·금액 수치가 등장하면 플래그.
- 검수 큐: 상태 `generated → lint_ok → review → approved → published`. 허브·topic 페이지는 100% 사람 검수, 지역 리프는 샘플 20% + 린트 통과 자동 승인(초기 3개월은 50%).
- 재생성·버전: `page_contents(combo_id, version, prompt_version, model, status, created_at)`; 공개 버전 포인터는 `pages.content_version`. 롤백 가능. 콘텍스트 데이터 변경(법원 이전 등)은 영향 콤보 재생성 작업 큐 생성.

| price_ranges | vertical, region_level, item, min, max, unit, source, as_of | 이사(평수·거리별), 인터넷(통신사 공시 요금), 렌트(차종별 월 렌트료), 법률은 "법원 예납금·송달료" 같은 공적 수치만 |
- 각 리프에 최소 2개 블록이 실데이터에서 채워지지 않으면 `publish` 불가(품질 게이트).

### 9.2 내부 링크 아키텍처
- 필러/클러스터: 버티컬 허브(필러) ↔ topic 허브 ↔ topic x intent/situation/persona 리프. 모든 리프는 부모 허브로 1개, 형제 3~6개, 관련 다른 topic 2~3개 링크.
- 지역 메시: 리프에 부모(시도/시군구), 형제(같은 부모 하위 최대 12개, 인구 순), 인접 지역(지오코드 거리 또는 수동 `region_adjacency`), 같은 지역 다른 topic 링크. 동 페이지는 부모 시군구와 형제 동만(링크 수 절제).
- 관련 키워드 블록: 콤보의 `cannibal_group` 내 비대표 키워드는 앵커 텍스트 변형으로 활용, 그룹 외 연관 콤보 4~8개를 "함께 찾는 정보"로.
- 블로그/qna → 머니 페이지: 본문 중 첫 등장 topic 키워드에 contextual 링크 1~2개 + 하단 "지역별 상담처" 블록(상위 17 시도 전부가 아니라 글의 지역 언급·방문자 지역 상위 6개).
- 브레드크럼: 앵커에 topic 키워드 포함("인천 개인회생 > 부평구 개인회생"), 항상 BreadcrumbList와 일치.
- HTML 사이트맵: `/사이트맵/`(버티컬·topic·시도), `/{버티컬}/사이트맵/지역/`(시군구 전체), 동은 시군구 페이지에서만.
- 링크 수 상한: 본문 내 내부 링크 ≤ 100, 전역 nav 드롭다운은 SSR 포함하되 리프에서는 시도 17 + topic 목록만(서비스 x 지역 전 조합 금지).
- 앵커 텍스트 규칙: 같은 대상 페이지로 가는 앵커는 사이트 전체에서 3~5개 변형을 로테이션(`anchor_variants` 테이블), 동일 페이지 내 중복 앵커 금지, "여기", "자세히" 금지.

### 9.3 네이버 특화
- 등록: 서치어드바이저 사이트 등록(HTML 태그), robots 검증, 사이트맵 인덱스 제출, RSS 제출, 핵심 허브 "웹 페이지 수집 요청"(일 한도 있음, 확인 필요), 사이트 간단체크로 title/description 중복·누락 점검. 다음(검색등록) 등록, 빙 웹마스터(IndexNow 키 공유), 구글 서치콘솔 도메인 속성.
- 사이트 구조: 네이버는 사이트 단위 신뢰(C-Rank: 출처의 주제 집중도·맥락, 공개 설명 기준)와 문서 단위 품질(D.I.A.: 문서의 정보성·경험·독창성, 공개 설명 기준)을 함께 본다고 설명한다. 내부 동작은 비공개이므로 "한 사이트가 한 주제에 집중하고, 문서마다 고유 정보·경험·출처가 있어야 한다"는 운영 원칙으로만 반영한다. → 디렉터리 전략(6.3)과 버티컬별 작성자·편집기준 페이지가 여기에 대응.
- 연관채널: 서치어드바이저의 연관채널에 네이버 블로그·포스트·카페·유튜브 연결. 외부 채널(네이버 블로그·카페·지식iN 답변·플레이스(실사업장이 있을 때만))에서 사이트로 자연 링크. 지식iN 답변에 링크 남발은 제재 대상이므로 답변 품질 우선.
- 스마트블록·지식스니펫 대응 포맷: 질문형 H2 + 첫 문단 2~3문장 직답, 표(비용 구성·기간·서류), 번호 절차(ol), FAQ `<details>`, 용어 정의 블록. 문서 상단에 "핵심 요약" 3줄.
- 신선도: 허브·topic 페이지 분기 1회 실데이터 갱신(법원 비용표, 통계) + `dateModified` 실제 갱신, 블로그 주 3~5편, 변경 없는 페이지 lastmod 조작 금지.
- 네이버는 서브도메인을 별도 사이트로 보므로 디렉터리 전략이 사이트 신뢰 축적에 유리(6.3). 모바일 우선: 네이버 모바일 검색 비중이 크므로 모바일 템플릿 성능 기준 우선.

### 9.4 콘텐츠·E-E-A-T
- 작성자 페이지 `/작성자/{slug}/`: 운영사 편집팀 실명(또는 필명+실제 운영자 책임 표기), 경력, 연락처. 법률 콘텐츠는 "검토: 광고책임변호사 아님 — 외부 전문가 검토 여부"를 사실대로. 검토자가 없으면 "법률 자문이 아닌 일반 정보" 고지로 대체(허위 검토자 금지).
- `/편집기준/`(콘텐츠 작성·갱신·출처 원칙), `/광고고지/`(수수료 구조, 오퍼 선정·순서에 영향 명시 — 참조 사이트 about의 문구를 더 구체적으로), `/운영사/`(상호·대표·사업자등록번호·주소·이메일).
- 각 문서 하단 "출처": 법령정보센터 조문 링크, 법원 안내 페이지, 공공데이터 출처·기준일. `topic_facts.source_url`에서 자동 출력.
- 갱신일 표시: `dateModified`를 본문 상단에 노출, 실제 변경만.
- 링크 유도 자산(도구): 개인회생 변제금 계산기(월 소득·부양가족·최저생계비 기준 입력 → 추정 변제금, 가정·출처 명시), 개인회생 vs 파산 자가진단 체크리스트, 이사 견적 계산기(평수·거리·옵션), 입주청소 비용표, 인터넷 요금·사은품 비교표(통신사 공시 기반, 갱신일), 장기렌트 월 렌트료 비교표(차종별), 법원별 예납금·송달료 표. 도구는 JS 최소·서버 계산 가능하게, 결과 공유 URL 제공.
- 공공데이터 원본 페이지: 시도별 개인회생·파산 접수 건수(법원 통계월보, 공개 범위 확인 필요), 지역별 다중채무자 통계(공개 자료 범위 확인 필요) → 연 1~2회 갱신하는 데이터 페이지가 자연 링크를 받는다.

### 10.3 콘텐츠 조립(요청 시, 콤보 기준)
```
render_combo(combo):
  if pages.cache valid (cache_version, ranking_version 일치) → return rendered_html
  content = page_contents.get(combo.content_version)          # 승인된 생성 블록
  region, topic, facts = load_context(combo)                  # regions, region_facts, region_programs, topic_facts, price_ranges
  offers_main = select_offers(combo, 'cards', n=vertical.card_count)   # 7.6, 결정적
  offer_form  = select_offers(combo, 'form', n=1)
  links = build_links(combo)                                   # parent, siblings(≤12), adjacent(≤6), related_combos(4~8), other_topics(2~3), anchor_variants
  faqs = content.faqs or faq_pool.pick(topic, n=4, seed=combo.id)   # 생성 FAQ 우선
  jsonld = [org_website(), breadcrumb(combo), faqpage(faqs) if faqs, itemlist(links.children) if hub]
  html = render_template(f'pages/{combo.page_type}.html', ...)
  pages.upsert(rendered_html=html, content_hash=md5(content.blocks+faqs+offer order), ...)
  if content_hash changed: combo.content_updated_at = now; indexnow_queue.add(url)
```
- 결정성: 오퍼 순서 시드 = sha256(site|combo.id|slot|ranking_version). 콘텐츠는 저장본이므로 요청 간 변동 없음.
- 품질 게이트(publish 전 배치): uniqueness_score ≤ 임계, lint_ok, 실데이터 블록 ≥ 2, 오퍼 ≥ 1(compliance_ok), 내부 링크 ≥ 5. 하나라도 실패 → status 유지(draft/review).

## 11. 리스크 및 차별화

(a) 대량 유사 페이지(도어웨이) 처리
- 네이버·구글 모두 지역명만 바꾼 동일 템플릿 페이지를 유사 문서로 묶거나 저품질로 분류할 수 있다. 참조 사이트가 사이트맵을 3,000개로 제한하고 회생OK가 서울만 제출하는 것도 이 때문으로 보인다(추정).
- 공개 속도: 주당 신규 index 상한 — 1~2개월 100/주, 이후 색인율(GSC·네이버 수집 비율) ≥ 70%이면 300/주, 그 외 동결. 동 페이지는 수요 확인 전 noindex.
- 중복 임계: 형제 페이지 5-gram Jaccard ≤ 0.35, 사이트 전체 템플릿 고정 블록 비율 ≤ 50%(실데이터·생성 블록이 절반 이상). 미달 시 publish 차단.
- 모든 리프에 실데이터 블록(관할 법원·주소·전화, 지역 통계, 지원기관, 가격 범위) 2개 이상.

(b) 복제 금지
- 참조 사이트의 문장 풀·FAQ·이미지·파트너 보일러플레이트를 그대로 쓰면 저작권 문제와 중복 콘텐츠 불이익이 동시에 생긴다. 구조(섹션 순서·슬롯·URL 규칙)만 가져오고 콘텐츠는 전부 자체 생성·검수한다. 이미지도 자체 제작.

(c) 이 버티컬에 적용되는 국내 규정(법률 자문 아님, CPA 네트워크 약관·변호사와 확인할 항목)
- 변호사 광고 규정(대한변호사협회): 광고책임변호사 표기, 결과·승소 보장 표현 금지, 비교·최상급 표현 제한 → compliance_schema.required=['ad_lawyer'], 린트 금지어.
- 변호사법 제34조·제109조(사건 알선 대가): 광고 매체로서 광고비(CPA)를 받는 구조와 알선 대가의 경계를 네트워크 약관·변호사와 확인. 자체 폼(own_form)으로 리드를 받아 법무법인에 전달하는 방식은 이 쟁점이 더 커질 수 있으므로 법무 검토 전 비활성(Phase 8).
- 표시·광고법 및 추천·보증 심사지침: 수수료 관계 고지(상단 근접 + 푸터 + /광고고지/), 근거 없는 "1위·최고" 금지.
- 개인정보보호법: redirect/iframe 모드는 수집 주체가 외부이므로 처리방침에 외부 폼 운영 주체 명시. own_form은 수집·이용 동의 + 제3자 제공 동의(제공받는 자·항목·목적·보유기간) 분리 체크, 암호화 저장, 보유기간 후 파기, 접근 기록.
- 버티컬별 추가: 대부·금융(대부업 광고 표시 의무, 경고문), 보험(보험대리점 등록 표기), 의료(의료광고 사전심의), 통신(약정·위약금 고지). 각 버티컬 활성화 전 compliance_schema에 반영.
- 운영자 정보 표기(상호·대표·사업자등록번호·주소·이메일)는 참조 사이트가 생략했지만 우리는 표기.

(d) 링크 네트워크
- 참조 사이트의 수십 개 `.ai.kr` 위성 도메인 회전 푸터 상호링크는 구글 링크 스킴·네이버 어뷰징 판정 리스크가 있다. 단기 노출 이득 vs 전체 네트워크 동시 패널티 위험의 교환이다. 우리는 소유 도메인 2~3개 이내, 전부 nofollow, 사이트당 노출 2개 이하, 주제 관련성 있는 것만. 외부 링크 획득은 도구·데이터 페이지와 외부 채널(네이버 블로그·카페·지식iN)로.

(e) 파이프라인 안전장치
- 린트·게이트는 코드로 우회 불가(CLAUDE.md 규칙). 모델·프롬프트 변경 시 샘플 50개 사람 검수 후 적용. 오퍼 compliance 미충족 시 자동 비노출.
